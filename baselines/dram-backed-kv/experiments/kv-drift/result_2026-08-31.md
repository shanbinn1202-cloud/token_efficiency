# KV-drift compatibility regression

> Status: retained compatibility regression.

## Scope

This experiment verifies that the new framework contracts can import the
recorded `astropy__astropy-13579` trajectory and offline Oracle, serialize the
resulting `TurnContext`, `PageCatalog`, `GoalRecord`, and `SelectionPlan`, and
drive the previously validated Qwen numerical replay engine without changing
the semantic result.

It is a compatibility regression, not a native DRAM/HBM runtime measurement.
The backing tensors remained on the GPU to isolate selection semantics.

## Environment

- DeltaAI GH200 120GB, BF16/SDPA.
- Qwen3.6-27B.
- Python 3.12.9, PyTorch 2.10.0+cu129, Transformers 5.14.1.
- 128-token logical Pages.
- Recorded Pure FullKV trajectory from job 3012104.
- Offline Oracle with future leakage; this is an upper bound, not an online
  Selector result.

Jobs:

- `3056285`: 100% active invariant, 40% budget, and turn-30 no-reactivation;
  completed in 6m49s.
- `3056342`: paired restored-Oracle baseline; completed in 1m34s.

## Results

### 100% active invariant

At the first selective turn (turn 9), both Reset-selected and
Cumulative-selected matched Dense exactly:

| Branch | max absolute logit delta | Delta NLL | top-1 agreement |
|---|---:|---:|---:|
| Reset-selected | 0 | 0 | 100% |
| Cumulative-selected | 0 | 0 | 100% |

### 40% active budget

The realized history-token-weighted active ratio was 40.021%. Across 10,554
selective action tokens:

| Branch | token-weighted Delta NLL | token-weighted top-1 agreement |
|---|---:|---:|
| Reset-selected | 0.08569878 | 96.7974% |
| Cumulative-selected | 0.08424989 | 96.5037% |

For every turn and branch, `active_tokens`, `delta_nll_vs_dense`, and
`top1_agreement_vs_dense` exactly match the old job-3048175 golden output.

### Turn-30 Page reactivation

The restored SelectionPlan contains 61 Pages including returning Page 112.
The ablation plan contains 60 Pages and removes only Page 112 at turn 30.

| Branch | Restored Delta NLL | Omitted Delta NLL | Omission penalty | Restored / omitted top-1 |
|---|---:|---:|---:|---:|
| Reset-selected | 0.07723229 | 0.60097736 | +0.52374507 | 93.75% / 91.25% |
| Cumulative-selected | 0.02520117 | 0.36732221 | +0.34212103 | 93.75% / 90.00% |

This reproduces the prior causal result while proving that the model backend
consumed the Page set serialized by the new framework.

## Conclusion

The old drift study does not need to be repeated in full. The new contracts
preserve its tokenization, Page selection, active-only replay, and metrics.
The next work should use the framework for Goal/Selector Shadow experiments,
then implement a native CPU-DRAM backend that separately proves physical HBM
release, delta restore, resident reuse, transfer cost, and concurrency gains.
