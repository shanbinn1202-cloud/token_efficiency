  - 在作业 3270721 的干净环境上（复用），4 个 session × 6 轮、每轮 6,500 token observation、24 GiB 的合成运行通过（Slurm 作业 3292739、3295203、3299809）。作业 3299809 中，四个请求同时 decode 时的稳态每 token 延迟为 82、82、71 ms（full、observation_query、goal_query），作业 3292739 中为 117、111、102 ms。同一模型的原版 vLLM 0.24.0 在四个请求同时 decode 时每步为 67 ms（作业 3291778，用同样方法测量；它的整轮平均为 85 ms，因为其中还包括被其他请求的 prefill 拉长的 decode 步），因此四个请求时本 runtime 每步仍慢 4–15 ms（67 ms 和这一差值未经复核：作业取回的证据中没有这个原版每步时间）。
  - 它还没有单独做干净安装验收。
- **更早的 runtime：commit `c1ad7fdc8209a370ef229defe44d4832cd40ad85`（2026-10-02）。** 它在下面的 runtime 上去掉了每个请求的额外开销。策略、选择和 agent 协议都没有变。

- **较旧的 runtime：commit `9430c695d60bd90ff4bc588f6316e6613681d3e2`（2026-10-01）。** 它在下面已验收的 runtime 上加了一个修复。
