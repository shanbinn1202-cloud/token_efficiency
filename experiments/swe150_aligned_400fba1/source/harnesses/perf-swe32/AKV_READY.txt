1. AKV'S RULE (arXiv 2610.28577, the HTML page) AND akv_rule
------------------------------------------------------------
The paper: its tool-response rolling-drop policy "retains the KV states of the latest 12 tool responses" (section 5.1);
section 3.2 keeps the cache of all reasoning and drops older tool-response cache; appendix A.4.2 starts the drop once
the tool responses exceed those 12 rounds; there is no token threshold for the drop. The paper names no rule for the
system prompt and task (only tool responses are dropped), drops at message granularity (message indices), and evaluates
mini-SWE-agent on SWE-bench Verified with 250 steps, on MoE models (MiniMax-M2.7, GPT-OSS-120B, MiroThinker-1.7-Mini).
akv_rule (f4ccd4b): attended = the mandatory Pages (system + task), every Page holding a token of any agent reply
(60c5d21's reply spans: generation header, reasoning, </think>, content, closing boundary; cover) and the Pages of the
latest 12 tool responses, the current observation counted as the newest (it is the live tail, always attended), so the
latest 11 sealed observation spans are kept whole; nothing else. A Page is dropped only when it lies wholly inside the
older tool responses. No budget (capacity = the rule's selection; --active-token-budget refused), no token threshold
(switch_threshold_tokens 0: the rule applies from local turn 1; until a 12th tool response it keeps every Page). A
rebuilt first request's history (no span splits it by role) is kept (the paper never drops reasoning). Per active turn
query.selection.window records selected_page_count, selected_tokens, reply_pages, kept_tool_responses (min(11, sealed);
the current one is the 12th), dropped_tool_responses, dropped_pages, first_tool_page / first_tool_position (the oldest
kept tool response), and the window fields (covered turns / tool responses).
Points where we deviate or had to choose (also in the runtime README section 5):
  (a) "the latest 12" includes the newest tool response (the paper does not say so explicitly); 12 sealed + the current
      one would be another pin value (one constant), if you prefer it;
  (b) positions: retained Pages keep their original positions (AKV's repos is not implemented);
  (c) dropped Pages stay in DRAM and the rule never selects them again (AKV prefers evicting dropped cache);
  (d) Qwen3.6's GDN layers keep a state of the whole history, the dropped tool responses included: the drop applies to
      the 16 full-attention layers only (the paper's models are MoE transformers with no such state described; not the
      dense models the brief mentions);
  (e) the server applies the rule itself; AKV's agent harness issues the cache operations with each request;
  (f) granularity: 16-token Pages by cover (a dropped tool response's tokens on a Page shared with a kept token stay
      attended; AKV drops whole messages);
  (g) our runs keep 120 steps (the paper's SWE-bench runs allow 250).
